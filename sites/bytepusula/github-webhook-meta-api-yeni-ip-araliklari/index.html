GitHub webhook teslimatlarına yeni IP aralıkları ekliyor; sabit izin listeleri etkilenebilir

Meta API'nin hooks alanı güncellendi. API'yi zaten izleyen sistemlerin bu ekleme için ayrı değişikliğe ihtiyacı yok.

BytePusula · 30.10.2026 · 2 dk okuma

Sessiz retlerin olası nedeni

GitHub, github.com üzerinden gönderilen webhook bildirimleri için yeni IP aralıkları duyurdu. Gelen isteği yalnız önceden yazılmış adreslerden kabul eden sistemlerde bu değişiklik önemli: yeni kaynaktan gelen geçerli teslimat, uygulamaya ulaşmadan ağ katmanında reddedilebilir. Duyuru, tüm planlardaki github.com teslimatlarını kapsıyor; yalnız Enterprise müşterilerine ayrılmış bir özellik değil.

Güncel listeyi API'den almak

Yeni aralıklar 9.234.98.160/28, 9.234.98.176/28 ve 9.234.106.48/28 olarak listeleniyor. Bunlar Meta API yanıtındaki hooks alanına eklenmiş durumda. GitHub, izin listesini bu API ile güncel tutanların ek işlem yapmasına gerek olmadığını belirtiyor. Sabit liste kullananlar içinse mevcut adresleri silmek yerine yeni aralıkların da değerlendirilmesi gerektiğini söylüyor.

Adres listesi tek başına güvenlik değil

Bu haber, okuyucunun güvenlik duvarını kontrol etmeden değiştirmesi için genel bir talimat değil. Teslimat sorunu incelenirken ağ kuralı, uygulama kaydı ve webhook doğrulama yaklaşımı birlikte ele alınmalı. IP eşleşmesi bir bildirimin içeriğini otomatik güvenilir yapmaz. Biz herhangi bir ağ kuralını değiştirmedik; aktardığımız bilgiler GitHub'ın 29 Ekim tarihli teknik açıklamasına dayanıyor.
