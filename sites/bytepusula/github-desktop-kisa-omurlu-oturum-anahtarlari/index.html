GitHub Desktop’ta kısa ömürlü oturum anahtarları kademeli açılıyor

3.6.10 ve sonraki sürümlerde desteklenen hesaplar, oturum açarken otomatik yenilenen anahtar alabiliyor.

BytePusula · 04.11.2026 · 2 dk okuma

Sürüm yükseltmek ve yeniden oturum açmak farklı adımlar

GitHub Desktop’ın 2 Kasım duyurusunda kısa ömürlü kimlik doğrulama anahtarları için iki koşul var. Uygulamanın 3.6.10 veya daha yeni olması ve dağıtımın hesaba ulaşması gerekiyor. Açık bir oturumla güncelleme yapan kullanıcı oturumunu sürdürebiliyor. Var olan anahtarların yeni türe otomatik geçirilmediği belirtiliyor. Yeni anahtar, destek erişilebilir olduğunda oturum açma sırasında veriliyor.

Yenileme uygulama içinde yürütülüyor

Uygulama bu anahtarları Git işlemleri ve GitHub API istekleri için kendisi yeniliyor. Kısa geçerlilik süresi, ele geçirilen bir erişim anahtarının kullanılabileceği pencereyi daraltmayı amaçlıyor. Bu dağıtım GitHub.com ile GitHub Enterprise Cloud hesaplarına kademeli ulaşıyor. GitHub Enterprise Server bu duyurunun kapsamı dışında. Dolayısıyla aynı sürüm numarası, iki farklı kuruluş ortamında aynı oturum davranışını garanti etmiyor. Ekipler kendi hesap türüyle ilgili bilgiyi kontrol ederek yükseltme ve oturum açma kararlarını ayrı ele alabilir. Özellikle ortak kullanılan iş akışlarında, uygulama sürümüyle hesabın dağıtım durumunu ayrı kaydetmek sorun teşhisini kolaylaştırabilir.
